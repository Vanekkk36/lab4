# Отчёт по лабораторной работе №4

## Данные и подготовка

Загружен `german.csv` с разделителем `;`: 1000 строк, 20 признаков и целевой столбец
`Creditability`. В целевом столбце 700 объектов класса `1` и 300 объектов класса `0`;
пропусков в таблице нет. Стратифицированный split с `random_state=42` выделяет 800
объектов для обучения и 200 для финальной оценки.

Категориальные коды полей `Account_Balance`, `Payment_Status_of_Previous_Credit`,
`Purpose`, `Value_Savings_Stocks`, `Length_of_current_employment`,
`Sex_Marital_Status`, `Guarantors`, `Most_valuable_available_asset`,
`Concurrent_Credits`, `Type_of_apartment`, `Occupation`, `Telephone` и
`Foreign_Worker` преобразуются через `OneHotEncoder(handle_unknown="ignore")`.
Числовые признаки и упорядоченные коды `Duration_of_Credit_monthly`, `Credit_Amount`,
`Age_years`, `Instalment_per_cent`, `Duration_in_Current_address`,
`No_of_Credits_at_this_Bank` и `No_of_dependents` передаются модели без изменения.
Их порядок в преобразованной матрице фиксирован в pipeline. Масштабирование не
применяется: выбранные модели — деревья, для которых оно не требуется. Заполнение
пропусков не нужно, так как в исходном CSV их нет. Encoder обучается внутри pipeline
на train-части каждого fold; категории, отсутствующие при обучении, игнорируются при
преобразовании.

Первоначальный вариант кодировал one-hot все 20 столбцов, включая сумму кредита и
другие числовые величины. При одинаковом split его прежние метрики воспроизводятся
(test ROC-AUC 0.79988 для Random Forest с `min_samples_leaf=2`), но такой вариант
не сохраняет порядок и числовой характер этих полей. Поэтому проверена смешанная
предобработка; результаты ниже соответствуют именно ей, кроме двух строк-контролей
с альтернативными способами кодирования.

## Гипотезы и эксперименты

Гипотеза: one-hot для кодированных категорий вместе с передачей числовых и порядковых
признаков без изменений лучше сохранит структуру данных, чем one-hot для всех полей.
Сравнивались Random Forest с `min_samples_leaf` 1, 2, 3 и 5, варианты `max_features`
(`"sqrt"`, `0.5`, `0.7`, `None`), Extra Trees с размером листа 1 и 2, а также
контрольные варианты Random Forest с one-hot всех признаков и без преобразования кодов.
В ансамблях использованы 500 деревьев и `class_weight="balanced"`.

Модель и параметры выбирались только по среднему ROC-AUC на 5-fold стратифицированной
кросс-валидации train-части. Test-метрики рассчитывались после выбора и не участвовали
в сравнении кандидатов. Полные fold-метрики и версии библиотек записываются при запуске
`py run_experiments.py` в `experiment_results.json`.

## Выбранная модель

Выбран Random Forest с 500 деревьями, `max_features="sqrt"`, `min_samples_leaf=2` и
`class_weight="balanced"`, использующий смешанную предобработку. Его средний train CV
ROC-AUC `0.78571` — наибольший среди проверенных кандидатов. Вариант с размером листа 5
получил лучший test ROC-AUC (`0.83500`), но меньший train CV ROC-AUC, поэтому он не
выбирался. ROC-AUC считается по вероятности класса `1`; бинарные метки берутся из
`predict` модели.

## Выводы и ограничения

Смешанная предобработка повысила train CV ROC-AUC относительно прежнего варианта
one-hot всех признаков (`0.78571` против `0.77515` для сопоставимого Random Forest).
Размер листа 2 дал лучший CV результат среди выбранных параметров, но не максимальный
test ROC-AUC или F1. Это показывает, что test нельзя использовать для подбора модели.
Датасет небольшой, поэтому оценка зависит от split; результаты относятся к одному
зафиксированному разбиению и не гарантируют такую же метрику на другой выборке.

## Воспроизводимость

Запуск из корня проекта: `py run_experiments.py`. Скрипт использует `german.csv`,
стратифицированный split 80/20 с seed `42`, `StratifiedKFold(n_splits=5, shuffle=True,
random_state=42)` и фиксированный seed моделей `42`. Он выбирает кандидата исключительно
по среднему train CV ROC-AUC, затем рассчитывает test-метрики, проверяет совпадение
результата контрактной функции с выбранным экспериментом и обновляет
`experiment_results.json`. Для сравнения результатов используйте один и тот же
интерпретатор Python и версии библиотек, записанные в JSON.
